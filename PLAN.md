# План: от дизайн-системы к экранам и передаче разработчикам

Рабочий документ. Обновляется по ходу работы. Статус на 2026-10-29.

## Как мы работаем

1. Владелец показывает макет (Figma) и говорит, что собрать.
2. Экран собирается в коде сразу, из готовых компонентов и токенов (`src/components`, `src/styles`). Недостающее — новым компонентом или токеном с обоснованием; токены заводятся и в Figma «02 — Tokens», и в `tools/raw`.
3. Результат смотрим на витрине (https://nikitatuia18.github.io/trust/), правки — сразу в код, коммит и пуш в `main` делаются сразу.
4. Разработчики забирают готовый код и подключают бэкенд. Дизайнер дизайн в Figma под код больше не привязывает (Code Connect не нужен).

## Что готово

- **Токены** (три уровня: Primitives → Semantic → Components) из Figma, генератор `npm run tokens`.
- **Компоненты** — все из «03 — Components» (волны A–F), у каждого на витрине Preview и Doc.
- **Правила** — вкладка «Правила»: 16 правил с живыми примерами.
- **Mobile** (< 768px) для Header, Mega Menu, Footer; Footer перестраивается и на средней ширине блока.
- **Экраны**: Регистрация, 3 шага (Email → Code → Details) — вкладка «Экраны» и отдельная страница `#/registration`. Код: `src/screens/`.

- **Экран Account / Affiliate program** (`src/screens/account/`, `#/account`) — тестовая сборка по макету «1.1 Account / Affiliate program»; в систему добавлены Badge, Breadcrumbs, StatTile, IconCircle, DropdownMenu, Table и расширения SegmentedControl size m, FormCard fluid. Шапка — системная (как у Auth Page), без аватара и без «Talk to sales».

- остальные экраны Auth Page из Figma: пароль, загрузка документа, KYC-вопрос (кадры 592:2139, 592:2232, 592:2242).

Для этого понадобятся компоненты, которых в системе пока нет (сейчас собраны вручную на экране):
- **OTP Input** — поле кода из ячеек;
- **Select** — выбор из списка (TextField + List; повторяется во второй раз);
- **Link** — ссылка внутри текста (сейчас локальный класс);
- **Document Upload** и **Question Row** — для экранов документа и KYC (Figma: Document Upload Placeholder, Question Row);
- состояние **loading** у Button (сейчас нет) и ошибки полей от сервера.

Затем — **Exchange Flow** (Sell S1–S5, Buy B1–B7 и поповеры сети, монеты, комиссии; всё на Form Card).

## Передача разработчикам — что нужно решить

Сейчас репозиторий — приватное Vite-приложение (витрина), а не пакет. Прежде чем отдавать код, нужны ответы разработчиков.

**Вопросы к разработчикам:**
1. Их стек и фреймворк на сайте: React (какая версия), Next.js, Vite? Экраны написаны на React 19 + TypeScript + чистый CSS с переменными.
2. Как им удобнее забирать код: копировать папки `src/components`, `src/styles`, `src/screens`; подключать как npm-пакет (приватный реестр); общий монорепозиторий?
3. Как они подключат бэкенд: REST, GraphQL, SDK? Кто отвечает за валидацию и ошибки сервера?
4. Нужны ли им i18n (тексты сейчас английские, зашиты в код), тесты, Storybook?
5. Как делается роутинг между шагами флоу (сейчас шаг хранится в состоянии `RegistrationFlow`).

**Что подготовить с нашей стороны (после ответов):**
- **Контракт экранов**: у каждого шага явные props и колбэки (`onContinue`, `onVerified`, `onChangeEmail`, `onFinish` и т. п.), типы данных, состояния «загрузка» и «ошибка от сервера». Сейчас это тестовая логика на клиенте (любой код из 4 цифр подходит).
- **Документ для разработчиков** (в README или отдельно): структура репозитория, как подключить токены и шрифты, как обновлять токены из Figma, пример подключения экрана.
- **Формат поставки**: либо оставить копирование папок, либо сделать сборку в пакет (library mode Vite, экспорты, типы).
- **Проверки качества**: автотесты компонентов и флоу, проверка доступности, проверка mobile на реальных ширинах.
- **Тексты**: вынести в словарь, если нужен i18n; заголовки шагов 2–3 регистрации придуманы без макета — согласовать.

## Договорённости и ограничения

- **Экраны собираются только из наших компонентов и токенов.** Макет Figma даёт логику и вид (что где стоит, какие состояния), но не состав компонентов: если в макете шапка, кнопка или иконка нарисованы иначе, чем в системе, берём системные; недостающее — новым компонентом системы, а не одноразовой версткой. Нарушение (Account, шапка по макету) — исправлено. Журнал ошибок: `docs/SCREEN-BUILD-ERRORS.md`; черновик промта для сборки экранов: `docs/PROMPT-BUILD-SCREEN.md`.

- Осознанные исключения, которые не пересматриваем: контраст Content/on-brand на Brand (3.14, hover 3.73), on-success на Success (3.54), crypto в Method Icon (2.98); подсказка в поле — Content/tertiary (≈3.7); ширина столбца Mega Menu 298 — локальное значение.
- Spinner вращается в коде (в Figma статичен), Avatar без фото показывает инициалы, у BOG и Credo в BankLogo буква-заглушка.
- Сырых значений и примитивов в компонентах нет; единственные исключения перечислены на странице «Правила».
